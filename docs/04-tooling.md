# 工具与"看不见图"时怎么办

## imgcheck.py —— 结构自检

纯 OpenCV，不依赖任何模型，跑得快，判据稳定。

```bash
python3 tools/imgcheck.py 图.png                # 基本：尺寸、alpha、留白、贴边、连通域、调色板
python3 tools/imgcheck.py 图.png --grid 12      # 网格混色（有没有半格脏色）
python3 tools/imgcheck.py 图.png --sym           # 左右对称（镜像 IoU / 面积比 / 重心偏移）
python3 tools/imgcheck.py 图.png --ref 上一版.png  # 与上一版比 IoU
python3 tools/imgcheck.py 图.png --scene         # 场景图跳过贴边判定
```

判据（写死在工具里，不靠眼力）：

| 项 | 通过标准 |
|---|---|
| 正/背面视图左右面积比 | 0.90 ~ 1.10 |
| 左右重心偏移 | < 1.5% |
| 镜像 IoU | > 0.88 |
| 单角色连通域 | 1（多一块就是断肢或孤立碎像素） |
| 网格混色率 | 0% |

已知误报：整幅铺满的场景（四边都是内容）会被判"四处贴边"，用 `--scene`。

## ascii_preview.py —— 文本预览

看图能力不可用时的最低兜底：把图缩成字符画，只看轮廓、比例、有没有大片空洞。

```bash
python3 tools/ascii_preview.py 图.png -w 60                 # 按色相分类
python3 tools/ascii_preview.py 图.png -w 60 --mode alpha    # 只看形状轮廓
```

能看出：形状是否成立、主体占比、有没有断裂、是否出框。
看不出：配色好不好看、线条干不干净、有没有细微错位。

## "看图工具挂了"这件事

多模态看图是**运行环境提供的接口**，不是项目里的代码。它报错时，能在项目侧做的是三件事：

1. **重试**（可能是临时故障，几分钟到几小时后恢复）
2. **量化兜底**：imgcheck 跑一遍，把"有没有断肢、是否出框、是否对称、有没有混色"这些客观项确认掉
3. **文本预览**：ascii_preview 确认形状和比例

做不到的是：确认配色和笔触是否好看。这件事只能人看。

所以规矩是：**没看过图，就不能说"我看过了"**。交付时明确写"这版我没能自行确认，请你看一眼"，并说明已经做过的量化检查项。假装确认过，是最贵的错——对方按"已经验过"的前提往下走，问题会在更后面才爆。

## 本地跑视觉模型为什么不行

试过，结论是不划算：

- 3 核 / 4GB 内存，跑 7B 级 VLM 会 OOM
- GitHub release 下载 30 秒 0 字节，HuggingFace 不通，模型权重下不来
- `ollama` 装不上

真要自建，得有独立显卡的机器；在创作机器上没必要。可行的替代是接一个云端视觉 API（需要自己的 key），把它包成一个 `describe_image.py` 放进来——但那是"换一个看图接口"，不是"修好原来那个"。
